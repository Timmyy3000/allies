Temporary Expo Go bridge

Copy one code. Keep the real PKCE session boundary.

Cloud renders the existing one-time exchange code after Google completes. Expo Go pastes it into the initiating attempt, which must still prove the in-memory PKCE verifier before the existing session path runs.

Why this change exists

Expo Go cannot complete the claimed-link return required by the accepted native Google flow, so Android and iOS testing stalls after Google authentication while Apple enrollment and native app-link setup are pending. This temporary mode is for Allies developers and testers. It preserves Google identity verification, AUTH-002 exchange/session behavior, and the current post-sign-in and onboarding continuation.

Compatible default

Redirect mode

Omitting completion_mode keeps the existing 303 redirect, callback state validation, and app-link exchange behavior.

Temporary opt-in

Manual-code mode

Cloud returns a protected HTML page with the same short-lived exchange code. The app pastes it into the same token exchange using the original verifier and redirect binding.

User outcomes

  1. An Expo Go tester can copy a short-lived code from the completed Google page and paste it into Allies on Android or iOS.
  2. Cancel, expiry, wrong-device paste, retry, and screen exit fail safely; an old attempt cannot install a later session.
  3. Redirect remains the default and manual delivery reuses AUTH-002, so removing the temporary bridge does not disturb production flow.

Bounded scope

Included

  • Optional completion_mode, persisted on the authorization transaction with redirect as default.
  • manual_code callback HTML with the existing 32-byte URL-safe code, copy control, selectable fallback, existing expiry, and no expiry extension on callback retry.
  • Exact redirect allowlisting, Google verification, transaction locking, PKCE S256, single-use exchange, refresh storage, account load, and navigation reuse.
  • EXPO_PUBLIC_NATIVE_AUTH_COMPLETION_MODE, defaulting to redirect and set to manual only in temporary Expo Go environments.
  • Manual entry plus explicit begin, exchange, cancel, restart, and unmount ownership.
  • Additive OpenAPI publication and Interface pinning.

Excluded

  • Device-code protocol, polling, second exchange system, custom short-code table, native Google SDK, WebView, or browser-cookie transfer.
  • Access/refresh token changes, refresh rotation, logout, SecureStore, account/profile/Workspace, or onboarding contract changes.
  • Replacing the claimed HTTPS return path. Manual mode retains the same allowlisted redirect_uri as an exchange binding without navigating to it.
  • Changes to the separate hosted callback/link service, production promotion, or removal of real-development-build acceptance gates.

Plan hygiene: the committed artifacts contain repository-relative paths and deployment placeholders only. The callback page must not expose provider credentials, Cloud access or refresh tokens, profile data, or the app verifier.

Dependencies and invariants

  • Cloud native auth is enabled and Google already returns to GET /api/v1/auths/native/callback/google.
  • The existing exchange code is 32 random URL-safe bytes, sealed at rest, single-use, and configured for a 60-second lifetime. UI behavior reads the configured expiry and does not hardcode it.
  • Only the opaque refresh token remains in SecureStore. State, verifier, pasted code, access token, and form state remain in memory.
  • The current NativeSessionAdapter.completeSignIn remains session authority, after it becomes cancellable and generation-safe.

Manual callback response

Semantic HTML provides a read-only/selectable code, a Copy sign-in code button, absolute/remaining expiry guidance, and restart instructions. A tiny nonce-protected clipboard script powers the button; selection remains the fallback when clipboard access is denied.

Cache-Control: no-store · Pragma: no-cache · Referrer-Policy: no-referrer · X-Content-Type-Options: nosniff · CSP default-src 'none'; style-src 'unsafe-inline'; script-src 'nonce-<per-response-nonce>'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'.

No Location header, external asset, or analytics request is present. The exchange code appears only in the HTTPS response body. Google’s provider code remains in the incoming callback URL because the provider protocol requires it.

Files: auth schemas, native API/controller, model, native authorization service, one migration, auth/OpenAPI tests, and integration handoff.

Exit: redirect is unchanged; manual callback reuses one exchange code and never extends expiry or mints a second session.

2 · Publish and consume in Interface

Add completionMode mapping/tests, pinned OpenAPI generation, environment parsing, manual code UI, Linking.openURL, abort threading, and adapter-owned serialized generation/commit safety across remounts.

Files: cloud-client native auth/tests/generated schema; mobile env/example; Google flow/hook/screen; session adapter/context; focused tests and docs.

Exit: old callers redirect; manual clients opt in; browser return, success, explicit cancel, retry, expiry, wrong-device paste, unmount/remount, and late exchange/storage are truthful; stale work neither survives nor clears a newer session.

Release order is a separately authorized gate

Implementation and delivery stop at validated, reviewable Cloud and Interface changes/PRs. After separate user approval, migrate and deploy Cloud, smoke omitted-field redirect (303) and explicit manual callback (200), then enable the manual mobile staging environment. An old backend may ignore the additive field and still return 303, so mobile enablement cannot precede Cloud proof. Android/iOS live evidence follows staging deployment.

Acceptance criteria

  1. Omitted mode preserves the existing 303 app redirect.
  2. Manual transactions return no-store, CSP-restricted callback HTML with the existing exchange code only in the body.
  3. Callback replay does not extend expiry or create another code; consumed/expired attempts reveal no code and show restart guidance.
  4. Pasted code succeeds only with the initiating verifier and same exact redirect. Wrong device/verifier/redirect, expiry, and replay issue no session.
  5. Manual mode is exposed only by explicit environment setting; source omission stays redirect.
  6. Pasted code, verifier, state, and access token remain in memory. Only the current opaque refresh token reaches SecureStore after valid exchange.
  7. Returning from/dismissing the browser keeps an unexpired attempt waiting for code. Explicit cancel, navigation, or unmount invalidates it; late begin/exchange/storage cannot publish stale UI, leave a stale token, or clear a newer session.
  8. Success uses existing session/account completion and validated post-sign-in/onboarding navigation.
  9. OpenAPI, pinned types, docs, and checks agree. Separate user approval is required for merge, migrate/deploy, staging smoke, and environment mutation; Android/iOS Expo Go evidence is the post-deploy gate.

Implementation constraints that protect the boundary

Backend

Reuse the existing callback transaction lock, indexed state digest, and one-to-one exchange lookup. Reading mode from the locked row adds no callback query, polling, collection relation, or prefetch path.

Cover manual persistence/render/exchange; omitted/default/invalid mode with 422; HTML escaping; CSP nonce agreement; clipboard fallback; safe provider failure; redirect mismatch; malformed code; no secret headers; duplicate callback same-code/same-expiry; callback claim races; exchange replay; wrong verifier that does not burn the rightful code; and consumed/expired pages without code.

Frontend

The flow owns only request-local verifier, state, abort controller, pasted code, and UI lifetime. The hook exposes only UI-safe state. The adapter is sole durable token, generation, and serialized commit/cleanup authority across remounts.

Restart follows serialized cleanup. Check generation/abort before write and publication. A delayed stale write plus immediate remount/retry must neither survive nor erase the newer session. Add no polling, cache, Zustand, AsyncStorage, native clipboard dependency, or code analytics.

Material risks and rollback

Copied code exposure

The code may be screen-captured or shared. Keep it in the HTTPS body, send no-store/no-referrer/CSP, preserve configured 60-second expiry, single use, redirect binding, and PKCE. Code alone cannot create a session.

Cancellation race

Adapter-wide generation, serialized non-cancelable commit/cleanup, cleanup-before-restart, and delayed-write plus immediate remount/retry tests prevent stale persistence or deletion of a newer session.

Rolling Cloud versions

Use a persistent database default of redirect, migrate/deploy Cloud first, and smoke both modes before mobile enablement.

Temporary mode drifts into production

Use explicit mobile environment selection, server default redirect, temporary-mode documentation, and no source-controlled production setting change.

Rollback

Unset the mobile setting or select redirect. The Cloud addition can remain dormant. Later removal deletes manual UI/rendering and the transaction column only after no deployed caller requests manual_code.

Resolved decisions

  • The existing Cloud callback renders the page; the separate hosted link callback is not a dependency.
  • The current random exchange code and token endpoint remain; no short code or polling protocol is added.
  • Delivery mode is persisted per transaction, so later environment changes cannot alter callback/replay behavior.
  • redirect_uri remains in manual start/exchange for allowlist and binding even without callback navigation.
  • The mode is temporary and opt-in; redirect remains the compatible default.
  • Manual mode uses Linking.openURL; browser return is expected, and only explicit cancel/navigation/unmount invalidates the attempt.
  • Cloud migration and behavior precede the mobile setting. Merge/deploy/environment mutation require separate user approval after validated PRs.
