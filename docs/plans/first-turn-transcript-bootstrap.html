Implementation plan · 4 September 2026 · Cloud + Foundry

Give Hermes the greeting it is replying after

Bootstrap the exact Cloud greeting into a new profile session before the first user reply is dispatched. One private capability closes the transcript gap without adding a queue, table, or history-import API.

1 · 1 · 0 One assistant seed, one model stream, zero transcript rewrites.

Feature overview

Current gapCloud remembers. Hermes does not.

The greeting is durable as Cloud message 1, while the first execution sends only message 2.

Synchronization pointThe first execution

Its immutable command already owns correlation, ordering, fingerprinting, and retries.

Resultassistant → user → assistant

The durable Hermes transcript matches the conversation the person saw.

User stories

Coherent first reply

Anonymous and signed-in creation reach the same transcript path.

Safe retry

An interruption converges without a duplicate greeting or second stream.

Operable failure

Conflicts fail closed with identifiers and stable reason codes, never content.

Scope

Included

  • Optional typed bootstrap in the existing command.
  • Immutable Foundry execution and claim carriage.
  • One private profile-scoped Hermes endpoint.
  • Pre-dispatch response-loss handling.
  • Exact-match legacy soul cleanup.
  • Tests, rollout, rollback, and Nabu update after validation.

Excluded

  • General transcript import or repair.
  • Direct SQLite writes from the runtime.
  • New queues, workers, tables, or dependencies.
  • Changes to onboarding UI or CLD-009 authentication.
  • Backfilling established sessions.
  • Rewriting custom or uncertain souls.

Acceptance criteria

  1. Exact Cloud greeting reaches first Hermes session.
  2. Persistent order is assistant, user, assistant.
  3. Exact retry creates no duplicate or second stream.
  4. Mismatched, late, established, malformed, unauthorized, non-loopback, and wrong-profile requests do not mutate history.
  5. Later turns omit bootstrap.
  6. New souls contain durable behavior only.
  7. Custom and uncertain souls stay byte-identical.
  8. Anonymous and signed-in paths show one greeting.
  9. Repository, image, and durable-storage proofs pass.
  10. All PRs are mergeable with terminal passing Enkii reviews and no unresolved P0-P2.

Backend considerations

Cloud

At most one indexed lookup on (conversation, sequence=1) for the first dispatch. Zero later-turn query change.

Foundry

Reuse the existing binding/execution transaction and JSON payload. No new relation traversal.

Hermes

One session lookup and at most two ordered message rows inside BEGIN IMMEDIATE.

Failure tests that protect the boundary

Concurrent identical requests, identity/content mismatch, unrelated existing history, response loss before acknowledgement, malformed success, SQLite rollback, soul write failure, and every auth/profile boundary are first-class test cases.

Frontend considerations

No frontend changes. Both entry paths already converge after Cloud persists the greeting and first user reply.

Rollback boundary

Roll Cloud back first to stop new optional fields. Roll the Foundry worker and derived image back together. Never delete a seeded row or replay an attempt after execution.dispatched.
