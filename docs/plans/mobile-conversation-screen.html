Mobile conversation screen layout and presence

Align the logged-in conversation with onboarding, keep one Ally presence below the latest content, and preserve the latest view while the conversation or keyboard changes.

Platform
Expo SDK 57 / React Native
Runtime
Local mobile conversation prototype
Behavior
Follow latest content

Core constraint: this is a presentation-only change to the current mock route. Cloud transport and persisted conversation contracts remain unchanged.

Requested outcome

  • Start logged-in conversation copy at the onboarding-equivalent vertical position.
  • Remove the visible Ally name and per-message blobs.
  • Keep one 33.6px blob below the latest user or Ally content.
  • Reuse the existing Thinking shimmer beside that same blob while replying.
  • Follow typewriter growth, new messages, keyboard layout changes, and composer focus while the user is near the end.

Implementation phases

1. Presentation model

Reuse the onboarding spacing constants, remove the identity row and message-level Ally previews, and append one status-owned preview after the message list. Use the existing idle and thinking artwork states.

2. Follow-latest behavior

Track whether the user remains near the bottom. Schedule scrollToEnd after content-size, layout, message, typewriter, keyboard, send, and focus changes. Manual history scrolling disables the automatic follow until the user returns near the end.

3. Proof

Test the pure near-bottom geometry rule, then manually verify the single trailing preview and keyboard behavior on Android and iOS. Run the mobile lint, typecheck, bundle, full test suite, and diff checks.

Acceptance criteria

  1. The opening logged-in message starts at the onboarding-equivalent 78px inset below the safe-area top.
  2. Manual device verification shows exactly one Ally preview and it follows all conversation messages.
  3. The preview is 33.6px, left-aligned, idle when settled, and thinking while replying.
  4. Thinking uses the existing shimmer and the same preview, without a duplicate blob.
  5. New content follows only while the user is near the bottom.
  6. The safe area, composer, mock send flow, and reduced-motion behavior remain intact.
