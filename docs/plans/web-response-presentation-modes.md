# Web response presentation modes

Route: fast. Branch: `web/ft/response-presentation-modes`; base: `dev` (`486ae6c`). HTML required: no; existing UI patterns and this behavior contract are reviewable in Markdown. Scope is Interface presentation/configuration; delivery is a PR, with no deployment mutation.

## Outcome and evidence

The web client will offer `NEXT_PUBLIC_RESPONSE_PRESENTATION_MODE=stream|aggregate|paragraph`, defaulting to `stream`. Stream mode reveals final assistant response text progressively while the turn runs, with locally paced presentation of uneven incoming bursts. Paragraph mode reveals each paragraph once its closing blank line arrives, batching updates between word-by-word streaming and waiting for completion. Aggregate mode retains the buffer-until-terminal behavior as an explicit rollback setting. The active status line displays meaningful safe activity labels while retaining the expanded history.

Inspected `AGENTS.md`, `apps/web/AGENTS.md`, `ENGINEERING_STYLE.md`, episode state, README, package scripts, Vitest configuration, and `.github/workflows/ci.yml`. Nabu's `projects/allies/index.md` and `projects/allies/engineering/specs/conversation-and-streaming.md` establish Cloud ownership, cursor replay, safe activity text, and the prior buffer-only presentation decision. This user request supersedes that presentation decision; the orchestrator must reconcile the canonical note with revision-aware update and readback.

Current code evidence:

- `conversation-frame.tsx` returns nothing for pending `TurnMessage` instances. Newly completed turns use Streamdown's word animation (`duration: 180`, `stagger: 24`, `maxBacklogMs: 2400`) and become static after 2800 ms. Reopened completed history is static.
- `conversation-frame-model.ts` merges projected turns with full-prefix durable replies, preferring durable content even when its in-progress snapshot may lag newer projected text. Legacy assistant messages already suppress duplicate projected replies.
- `home-workspace.tsx` receives `assistant_delta` through the existing projection and separately refreshes durable replies. Its upstream `mergeAssistantReplies`/`preferAssistantReply` chooses by timestamp and text length before status, so a shorter completion can be discarded before the frame model sees it. Transport enablement already uses `NEXT_PUBLIC_ACTIVITY_SSE_ENABLED`.
- `ActivityGroup` selects only unfinished lifecycle starts for its primary label, otherwise reverting to Thinking. `activity-presentation.ts` coalesces lifecycle entries and retains safe text, sequence, identity, and outcomes.
- `globals.css` disables Streamdown animation under reduced motion. Existing frame/model/workspace tests cover buffering, terminal reveals, history, truncated replies, activity lifecycles, and SSE recovery.

## Contracts and decisions

1. The public env selects presentation independently of transport. Only exact `aggregate` enables buffer-until-terminal presentation and only exact `paragraph` enables per-paragraph batching; missing, empty, `stream`, or unsupported values resolve to `stream`. Document the three supported values and build-time rebuild/redeploy requirement. No secrets, runtime toggle, backend flags, or wire changes are added.
2. Cloud remains authoritative. Use the existing typed turn identity and projector; do not append raw events into a second text store. Render each reply once beside its triggering user turn. Only associated assistant response text is eligible; tool payloads and unassociated pending fragments cannot become a live reply.
3. Apply durable reconciliation in both upstream `mergeAssistantReplies`/`preferAssistantReply` and downstream `mergeTurnModels`. For the same reply identity, a terminal reply supersedes an active reply regardless of shorter content or equal, invalid, older, or newer timestamps; an active snapshot never overwrites an accepted terminal reply. Between terminal replies, accept a replacement only when both timestamps are valid and the incoming timestamp is strictly newer; retain the accepted terminal on equal, older, or incomparable timestamps. Do not use content length as terminal freshness evidence. Preserve full-prefix completeness guards: incomplete content is never treated as the full answer. While active, prefer the longer compatible full prefix from snapshots/projection; never concatenate competing snapshots. On conflicting non-prefix content, preserve existing reconciliation semantics rather than guessing a join. Accepted terminal durable content wins exactly, including shorter or corrected content. Keep legacy-message deduplication, stopped/failed/truncated notices, access guards, and queue release independent of animation.
4. Smoothness belongs to rendering. Extend the existing Streamdown word animation to a growing target with a stable turn key; inspect its installed behavior before choosing additional machinery. Newly received words should progress at the existing bounded cadence without restarting already visible words. Catch up within 2400 ms of the latest received target; pause naturally when no text arrives. Use a small presentation-only scheduler only if the existing animation cannot satisfy this growing-target contract. Avoid a per-token durable queue or new dependency.
5. At terminal completion, reconcile to exact authoritative text and finish any bounded reveal without replaying the entire answer. Reopened completed history remains immediately visible. Reduced motion shows eligible text immediately, with neither animation nor an artificial pacing delay. Clear any presentation timers on unmount, turn/conversation switch, or target replacement.
6. For the current turn's primary activity label, prefer the latest meaningful unfinished activity; otherwise show its latest meaningful safe activity text with its actual completed/outcome wording. Use Thinking only before meaningful activity exists. Preserve approval/waking/sleeping precedence and existing terminal command wording. Do not label a completed action as still running, promote raw kinds/arguments, or borrow labels from a previous turn/Ally. Preserve activity count labels on completed history and the expandable entry list.
7. Keep growing Markdown outside any atomic live region and out of the active status node, including implicit atomic behavior from `role="status"`. A dedicated polite status announces meaningful activity transitions and one concise completion message per active turn, such as “Response complete”; never announce every text delta or repeat the full answer on append. The answer remains normally navigable reading content. Emit completion only when final content is available, retain failed/stopped outcome announcements, and do not announce historical replies on initial hydration. Use the same completion contract in aggregate and stream modes, deduplicated across replay/reconciliation.

## Risks, rollout, and unresolved decisions

- Existing word animation may smooth new DOM words without truly pacing appended Markdown blocks; verify bursts in a browser before deciding it meets the requirement. The bounded scheduler fallback is presentation-only and must honor reduced motion.
- Snapshot precedence can hide newer deltas or duplicate final replies. Upstream and downstream ordering tests are required before merging. Equal or invalid terminal timestamps cannot establish a newer revision, so retain the first accepted terminal rather than guessing by arrival order or length.
- Putting growing Markdown in an atomic status region can repeatedly announce the entire answer. The controlled status/completion contract and accessibility assertions are required in both modes.
- A latest completed activity is useful context but must keep past-tense/outcome wording. Approval and active-tool precedence prevent misleading status.
- Live text cannot arrive faster than Cloud forwards it. This setting does not activate SSE: near-live delivery still depends on the already documented Interface and Cloud SSE flags and deployment readiness. Polling fallback may deliver larger bursts that still receive local smoothing.
- Stream is the owner-selected default recorded in episode D2. Aggregate remains the explicit rollback setting. Timing uses the existing 24 ms word stagger/2400 ms backlog as the initial bounded default, subject to browser validation.
- Rollback: build/redeploy Interface with `NEXT_PUBLIC_RESPONSE_PRESENTATION_MODE=aggregate`; transport flags and persisted data remain valid. Enabling stream or deploying either mode is outside this planning episode's authority.
