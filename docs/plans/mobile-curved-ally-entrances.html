Mobile Curved Ally Entrances

A focused mobile motion refinement: replace direct entrance interpolation with four lightweight X/S-shaped curves while preserving the current GIF-backed screen.

Goal
Fluid curved entrances without a new runtime architecture.
Platform
Expo 57 / React Native / Reanimated
Branch
mobile/dev/onboarding

Core constraint: no Remotion motion code, frame table, new dependency, or per-frame JavaScript. The change stays inside the existing Reanimated transform path.

Scope

  • Add one pure, clamped cubic Bézier point helper.
  • Define four local curves with distinct control points.
  • Use the selected curve for actor translation only.
  • Keep timing, landing positions, GIF sizing, cursors, idle float, and reduced motion unchanged.

Motion contract

StateBehavior
OffscreenUse each Ally’s existing local start offset.
EntranceEvaluate a color-specific cubic curve with the existing eased entrance progress.
SettledEnd at local offset { x: 0, y: 0 } and preserve the current idle float.
Reduced motionSkip the entrance and keep the existing cursor-hidden behavior.

Task 2: Add the minimal helper

Create MotionPoint, CubicPath, ENTRANCE_CURVES, and the worklet-safe helper:

export function getCubicPoint(path: CubicPath, progress: number): MotionPoint {
  'worklet';
  const t = Math.min(1, Math.max(0, progress));
  const inverse = 1 - t;
  const inverseSquared = inverse * inverse;
  const tSquared = t * t;

  return {
    x: inverseSquared * inverse * path.start.x
      + 3 * inverseSquared * t * path.control1.x
      + 3 * inverse * tSquared * path.control2.x
      + tSquared * t * path.end.x,
    y: inverseSquared * inverse * path.start.y
      + 3 * inverseSquared * t * path.control1.y
      + 3 * inverse * tSquared * path.control2.y
      + tSquared * t * path.end.y,
  };
}

Run the focused test again. It should pass without importing Remotion.

Task 3: Integrate only the entrance translation

In ally-character.tsx, import the helper, attach the selected curve to the existing color motion config, and replace only the direct-plus-sine position expression:

const entrancePoint = getCubicPoint(motion.curve, easedEntrance);

return {
  positionX: entrancePoint.x + idleX * entrance,
  positionY: entrancePoint.y + idleY * entrance,
  rotation: motion.rotation * (1 - easedEntrance) + idleRotation * entrance,
  cursorOpacity,
  cursorX: Math.cos(cursorAngle) * pointerRadius,
  cursorY: Math.sin(cursorAngle) * pointerRadius,
  cursorScale: 0.75 + easedEntrance * 0.25,
};

Do not change the GIF source, artwork sizes, pointer styles, timing, cleanup, or reduced-motion branch.

Acceptance criteria

  1. All four curves start at their existing offsets and end exactly at { x: 0, y: 0 }.
  2. Each curve visibly deviates from its straight start/end segment.
  3. The existing 850ms entrance and 0/120/240/360ms stagger remain unchanged.
  4. GIF assets, Remotion-derived artwork proportions, blob sizes, final placements, cursors, idle float, and reduced motion remain unchanged.
  5. Motion uses only Reanimated derived values and transform/opacity styles.
  6. Focused tests, mobile lint, mobile typecheck, and git diff --check pass.

Risks and rollback

  • Too-subtle or excessive curves: adjust only the four local control points after inspecting the emulator.
  • Animation cost: keep all calculations inside Reanimated and retain fixed four-point paths.
  • Native build blockage: use the established temporary JS-bundle APK diagnostic flow without changing build configuration.
  • Rollback: remove the curve helper integration and restore the existing direct-plus-sine position expression.
