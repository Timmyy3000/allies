Accepted M2 implementation plan · 28 August 2026

Turn the polished onboarding into a working Allies app.

Build four Cloud-backed mobile destinations with the current design language and the smallest correct architecture. Map M3 and M4 now. Do not implement speculative screens.

Core decision Keep this M2 mobile slice as a stack. Reuse the existing onboarding, session, query, character, motion, Crypto, FileSystem, and SecureStore code. Add no dependency.

Outcome and boundaries

UsersSigned-in internal alpha testers

Create, open, use, and inspect an Ally through the public Cloud API.

Source of truthAllies Cloud

React Query caches fetched records. Mobile does not create a second product database.

NavigationSimple stack

Tabs arrive only when M3 adds three real root destinations.

Known contract ceiling: the 28 August staging contract is pinned at 1fceace3…b4f. It can create and retrieve an Ally, but it cannot list all Allies. M2 shows only Cloud-fetched Allies whose IDs are reachable in the current signed-in app lifecycle. It does not persist or invent a catalog.

Six implementation phases

Phase 1

Pin the Cloud surface

Refresh OpenAPI, generate types, validate response envelopes, and expand protected path handling.

  • No parallel transport layer.
  • Focused mapping and auth tests.
Phase 2

Workspace and route guards

Apply an explicit session/status matrix, make /allies the signed-in entry, and keep Account reachable.

  • One Load more count reveals 12 more.
  • Every row fetched from Cloud.
Phase 3

Official creation

Reuse onboarding, request the Cloud greeting, encrypt the exact command, authenticate, and create.

  • AES-GCM ciphertext in the app document directory.
  • Same-key recovery after OAuth or unknown outcome.
Phase 4

Continuous conversation

Render deduplicated ordered history, bounded pagination, composer, and safe activity text.

  • Cloud queues later accepted turns.
  • Three-second polling with a ten-minute ceiling.
Phase 5

Identity summary

Show the cached Cloud Ally as a read-only identity page.

  • No edit controls.
  • No unsupported product surfaces.
Phase 6

Verify and hand off

Review, run the full checks, test Android, update README and Nabu, and open a PR to dev.

  • Classify OTA eligibility.
  • Do not merge the PR.

Conversation merge and polling rules

HistoryBounded and ordered

Fetch the newest page first. Load older pages only on user action. Deduplicate by message ID and sort by Cloud sequence.

ConflictFail on incompatible copies

The same ID with different sender, content, or sequence is a contract error. Do not select one silently.

ActivitySafe projected text only

Render only ActivityResponse.text. Never expose kinds, IDs, payloads, or runtime fields as user copy.

Polling: poll every three seconds while focused and state is queued, in_progress, or running. Stop for awaiting action, terminal or unknown state, blur, unmount, or ten minutes. Keep manual Refresh.

Acceptance criteria

  1. Signed-in testers land on /allies.
  2. Auth return routes remain reachable.
  3. The workspace shows only Cloud-fetched Allies.
  4. The empty state explains the collection limit.
  5. Create Ally reuses existing onboarding.
  6. Creation uses the accepted body and a stable idempotency key.
  7. Creation failure preserves form data.
  8. Provisioning states come from Cloud.
  9. Conversation history follows Cloud sequence and cursor order.
  10. The composer blocks empty and parallel transport submissions, then allows later accepted Cloud-queued turns.
  11. Message retry keeps the same key and body.
  12. Polling stops after ten minutes or on paused, terminal, unknown, blurred, or unmounted state.
  13. Activity renders only ActivityResponse.text.
  14. Unknown states use a neutral fallback.
  15. Identity is read-only.
  16. Account and sign-out remain functional.
  17. Sign-out clears session-scoped state.
  18. Safe areas, keyboard dismissal, accessibility, and reduced motion remain correct.
  19. M3 and M4 remain documentation only.
  20. All repository checks pass.

Risks and controls

Missing collection read

Call this an M2 mobile slice. Do not persist a catalog. Replace the ID source when Cloud adds the endpoint.

Duplicate mutations

Encrypt one idempotency key and unchanged body before transport. Retry the same command after timeout, abort, remount, or restart.

Unknown lifecycle strings

Poll only queued, in_progress, and running. Stop and show manual Refresh for unknown or awaiting-action states.

Excess polling

Poll at three seconds only while focused and active. Stop after ten minutes or on blur, abort, paused, terminal, unknown, or unmount.

Auth route regression

Use explicit route guard tests for public, auth-return, signed-in, and signed-out paths.

Cross-account command

Expire pre-auth commands after seven days, bind once before transport, reject a principal or workspace mismatch, and clear on explicit sign-out.

Scope creep

No tabs, attachments, manual editors, runtime UI, analytics, flags, or new dependencies in M2.
