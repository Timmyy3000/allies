Feature overview

Outcome and boundaries

A person signs in with a verified external identity and consistently returns to the same Cloud actor. First sign-in atomically creates their editable profile, personal Workspace, active owner membership, and refresh-session family. Every later Workspace authorization is resolved from Cloud records—not token claims.

In scope

  • Google sign-in; ChatGPT only if ordinary consumer eligibility passes; deterministic fake provider for tests
  • Actor, identities, profile, session families
  • Personal Workspace, owner membership, capability map
  • Private R2 avatar lifecycle
  • CSRF, CORS, throttles, audit outcomes, isolation tests

Explicitly out

  • Passwords, magic links, MFA, recovery
  • Teams, invitations, extra member roles, billing
  • Ally, PreAuthContext, Foundry, Fly, Hermes, execution
  • UI implementation, account deletion, export

User stories

  1. 1 · Person

    Sign in without a password and return to the same account safely.

  2. 2 · Workspace owner

    Edit my name and avatar while remaining isolated from other actors.

  3. 3 · Operator

    Revoke sessions and inspect privacy-safe outcomes without handling provider secrets.

End-user eligibility and publisher setup

Ordinary users never need a developer or partner account

The Allies team may need OpenAI partner approval to offer the button. That is publisher setup, like creating a Google OAuth client. It is never an account requirement for the person signing in. ChatGPT stays in scope only if a normal consumer account can authenticate without API access or billing, developer/partner status, a paid business/workspace tier, or an invite.

Exclusion rule: if OpenAI's contract or sandbox shows that regular people are not eligible in the intended launch regions, ChatGPT is removed from AUTH-001 before provider code starts and the Nabu provider decision is revised.

Allies publisher

operator-only setup
  1. Create or use the company OpenAI Platform organization: platform.openai.com.
  2. While signed in, open the official partner verification route. Its public page does not promise self-service approval.
  3. Complete developer/business identity readiness and align the company name, website, support contact, privacy policy, and terms.
  4. Request explicit Sign in with ChatGPT partner enablement and a sandbox/test path.
  5. Obtain issuer/discovery, auth/token/JWKS or user-info endpoints, client ID/auth method, scopes, stable subject, nonce/PKCE rules, callbacks, brand/data terms, regions, and launch approval.
Separation: none of these Platform or partner steps are shown to an Allies user.

Ordinary Allies user

product requirement
  • Uses a normal Google account, or a normal consumer ChatGPT account only when the eligibility gate passes.
  • Does not create an OpenAI Platform organization, enable API billing, request partner access, or manage OAuth credentials.
  • Does not need ChatGPT Business/Enterprise, a managed workspace, a paid tier, or an invitation unless that restriction is compatible with the intended public audience—and the current requirement says it is not.
  • Can cancel provider consent and return to the provider picker without losing the Google path.
  • Sees clear provider availability for their country, age/account state, or temporary outage rather than an unusable button.
Acceptance proof: production-like smoke test with an ordinary consumer account that has no API or organizational entitlement.

Shared deployment prerequisites

Company Google OAuth project and consent screen; exact HTTPS callbacks; final Interface/Cloud origins; PostgreSQL; shared production cache; private R2 bucket and CORS; deployment secret store; scheduler/logging owner; staging test accounts; public homepage, support, privacy and terms URLs.

Architecture

Cloud owns identity and authorization

Two focused domains sit behind the existing Ninja Extra root API. Providers and object storage are narrow adapters; runtime domains never enter this slice.

Session lifecycle

Short access, rotating refresh

sequenceDiagram participant B as Browser participant C as Cloud participant P as OIDC provider participant D as Database B->>C: Begin sign-in C->>D: Persist one-time state + nonce + PKCE C-->>B: Redirect B->>P: Authenticate P-->>B: Authorization code B->>C: Callback with code + state C->>P: Exchange and validate claims C->>D: Atomic actor + workspace bootstrap C-->>B: Access + opaque refresh cookies B->>C: Rotate refresh token C->>D: Lock digest row, consume, issue successor C-->>B: New cookie pair

Authorization invariant

JWTs identify sessions—not authority

Allowed claims: iss, aud, sub, sid, jti, iat, exp.
Never claims: workspace, role, capability, provider token.
Each Workspace request reloads active membership, then checks the owner capability map in service code.
Missing or foreign resources collapse to the same privacy-safe denial.

Refresh exchange

Representative /auths/me shape

Provider boundary

Verify, normalize, discard

Adapter operations: build authorization request; exchange code; validate issuer, audience, signature, times, nonce and subject; return a small normalized identity.

Persisted: provider key, immutable subject, safe display snapshot, audit outcome.

Discarded: provider access/refresh tokens, authorization code, raw claims.

Implementation sequence: deterministic fake adapter and Google OIDC. ChatGPT is considered only after an ordinary consumer account passes the eligibility gate.

Two ChatGPT gates: first prove ordinary-user access; then obtain the publisher client contract. A failed first gate removes the provider. A passed first gate never permits guessed endpoints, claims, or browser-session scraping.

Avatar lifecycle

Private object, verified bytes

stateDiagram-v2 [*] --> Pending: prepare signed PUT Pending --> Ready: bounded GET + hash + Pillow verify Pending --> Rejected: missing / mismatch / unsafe image Pending --> Deleted: cleanup after 24h Ready --> Replaced: newer verified asset Ready --> Deleted: user deletes Rejected --> Deleted: bounded cleanup Replaced --> Deleted: bounded cleanup
Transport checks are not publication proof. Completion streams at most 5 MiB + 1 byte, computes SHA-256, sniffs and decodes one image, enforces 4096×4096 / 16MP limits, then locks the pending row before publishing it.

Delivery phases

One reviewable feature branch, five explicit gates

0 · Toolchain and deploy-contract gate

Install the repository's declared uv toolchain, run the untouched baseline, settle origins and infrastructure, configure Google's company OAuth project, document JWT/R2/cache settings, and add PostgreSQL CI. Before any ChatGPT code, verify that a normal consumer account needs no API, billing, developer/partner, paid-business/workspace, or invite entitlement across the launch audience. Exclude it and revise Nabu if that fails; only then pursue publisher onboarding if it passes.

Exit: baseline evidence captured; ordinary-user include/exclude decision recorded; included providers have complete operator configuration ownership.

1 · Principals, Workspaces, and migrations

Set AUTH_USER_MODEL before any persistent migration. Create auths/0001 first and make workspaces/0001 depend on it; name identity, state, digest, personal-Workspace, membership, and active-token constraints; then implement atomic bootstrap.

Exit: fresh SQLite and PostgreSQL migrations plus real collision/concurrency tests pass.

2 · OIDC and session transport

Implement browser-bound sign-in and authenticated link flows plus fake/Google adapters. Add ChatGPT only when Phase 0 marked it included and use its official contract. Add allowlisted redirects, active-family access checks, refresh locking/reuse detection, logout, exact cookie/CSRF/CORS settings, shared-cache throttles, audit events, and operator revocation.

Exit: Google passes; ChatGPT is either formally excluded or passes an ordinary-consumer-account smoke test plus contract tests; security and race suites pass.

3 · Self-profile, Workspace context, and avatars

Add /me, profile update, owner capability resolver, two-actor isolation coverage, R2 prepare/complete/read/delete services, image verification, and bounded cleanup command.

Exit: self-only and cross-Workspace negatives pass; pending objects cannot become visible without byte verification.

4 · Hardening and release evidence

Measure query counts, reach ≥90% line coverage in new domains, run formatter/linter/type/tests/checks/migrations, verify logs contain no secrets, test rollback switches, and update deployment/operator documentation.

Exit: full command evidence, configuration matrix, rollback drill, Google staging evidence, and ChatGPT inclusion/exclusion evidence are recorded.

Query and N+1 plan

Bounded reads on hot paths

  • /auths/me: load actor/profile/current avatar plus personal Workspace/active membership with deliberate select_related; capabilities are a code lookup.
  • Workspace context: one constrained membership query joined to actor and Workspace; never fetch then iterate relations.
  • Refresh: indexed token digest lookup inside transaction.atomic() + select_for_update(); family revoke is one set update.
  • Guardrails: assert exact or bounded query counts for /me, context resolution, and bootstrap repeat paths on representative fixtures.
  • No pagination is introduced because all endpoints are singleton/session operations.

Test plan

Security branches are first-class behavior

Identity

New/repeat/concurrent subject; equal-email separation; authenticated link; collision; provider outage and malformed claims.

Session

JWT claim/expiry/key cases; CSRF/origin; rotate; double-submit race; reuse family revoke; actor-safe logout.

Tenant

Atomic personal bootstrap; inactive membership; missing capability; two actors × two Workspaces; indistinguishable denial.

Avatar

Foreign key; missing object; wrong bytes/type/hash/size; image bomb limits; replace/delete; abandoned-object cleanup.

Risks and rollback

Fail closed, keep migrations additive

Audience restriction: ChatGPT is excluded before code if regular consumer accounts cannot use it; publisher access never becomes a user prerequisite.
Cookie topology: same-site is default; cross-site requires exact allowlists and credentialed CORS tests.
Replay races: database uniqueness and locks carry correctness; process-local locks never do.
Rollback: disable provider routes, revoke active families, expire cookies, stop signed URLs, retain additive tables for evidence and forward repair.
